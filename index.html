Why 4 Focused Packages Beat One Monolith

Monaco JSON Studio started as a single CLI taking 1, 2, or 3. As soon as each layout needed its own ergonomics—top-bar file picking for 1 pane, side-by-side independent headers for 2 panes, and pipeline layouts for 3 panes—splitting into one shared primitive and three focused packages made every CLI and codebase dramatically simpler.

The 4-Repo Suite

monaco-json-studio-base

Zero-dependency core generator, region builders (header/, body/, footer/), and browser Monaco runtime.

monaco-json-studio-single

1-pane studio with top-bar Select File / dataset picker so no vertical space is wasted on stacked headers.

monaco-json-studio-double

2-pane side-by-side studio where each pane owns an independent header and footer.

monaco-json-studio-triple

3-pane workflow studio built for Input → Spec → Output pipelines.

Story & Docs npm GitHub

Design Principles Shared Across All 4 Repos

  • src/v1/ Versioning Discipline: Every package exposes a thin src/index.js gateway over src/v1/index.js.
  • Region-First Organization: base organizes both generator and browser code into header/, body/, and footer/.
  • Declarative DOM Bindings: Browser interactions use dom-primitive-bindings (bindings.json + actions.js) via container delegation.
  • Non-Overwriting Output: Repeated CLI runs auto-increment (-1, -2, …) so existing studios stay intact.
monaco-json-studio-base (header / body / footer + Monaco + dom-primitive-bindings)
   ├── monaco-json-studio-single  → 1 pane  (top-bar controls)
   ├── monaco-json-studio-double  → 2 panes (independent per-pane headers & footers)
   └── monaco-json-studio-triple  → 3 panes (3-column pipeline studio)
